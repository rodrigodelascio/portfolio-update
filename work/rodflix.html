01The brief

THE ASSIGNMENT

BUILD A CATALOGUE
WITH A DATABASE
AND CONSEQUENCES.

The goal was to build a TV series catalogue with a real database, clear navigation between shows, seasons, and episodes, plus a working admin area for managing content.

In theory, lovely. In practice, it meant carefully designing a schema, wiring up CRUD features, keeping the interface readable, and preventing everything from collapsing when a user typed something creative into a search box.

RodFlix demonstrates server-side logic, database interaction, and a structured interface. It feels simple for the user while the back end quietly does the heavy lifting.

04Plot complications

EVERY BUILD NEEDS
A LITTLE DRAMA.

PROBLEM / 01

A database with too many opinions

Series, seasons, episodes, and related information needed to work together without turning every query into a small tragedy.

REWRITE / 01

Give every relationship a proper job

I built a clear relational structure and separated responsibilities so the application can grow without breaking everything that already works.

PROBLEM / 02

A busy back end, pretending to be simple

The interface still needed to feel obvious while fetching, filtering, and rendering dynamic data behind the scenes.

REWRITE / 02

Keep the user facing the right direction

Predictable screens, reusable patterns, and clear navigation let users move back up a level without becoming part of the catalogue themselves.

  2. 02

  3. 03

    Input validation is not a nice extra. It is self-defence.
